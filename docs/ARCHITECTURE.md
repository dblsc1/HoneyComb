# 架构说明

## 一句话

**事实只有一种：发生过的时间段。** 其余全是它的投影。

## 数据流

```
   浏览器                      api (FastAPI)                 MongoDB
  ┌───────┐  POST /timer/start  ┌──────────────┐  活状态一条  ┌──────────┐
  │ 蜂巢  │ ──────────────────► │ timer.service│ ──────────► │timer_state│
  │ 计时台│                     │              │             └──────────┘
  │       │  POST /timer/stop   │  组装事件     │  追加一条    ┌──────────┐
  │       │ ──────────────────► │              │ ──────────► │  events  │ ← 只追加
  │       │                     └──────────────┘             └──────────┘
  │       │  GET /views/*       ┌──────────────┐  现算        ┌──────────┐
  │       │ ◄────────────────── │  projector   │ ◄────────── │ planner  │
  └───────┘                     └──────────────┘             └──────────┘
```

- `events`：`session.completed` 一种类型就够了。带 `dedupeKey`，重复投递不会记两遍。
- `planner`：分区 / 项目 / 任务这三层的登记表，是"计划面"，可以随便改。
- `views/*`：把上面两者拼起来的只读视图。前端从不直接读库。

**为什么不存"这个项目一共花了多少分钟"**：存了就得维护它，维护就会漂。
现算的代价是每次多几毫秒，换来的是这个数字永远等于流水之和。

## 计时的三个动作

| 动作 | 接口 | 写了什么 |
|---|---|---|
| 开始 | `POST /timer/start {taskId}` | 活状态一条；上一段没停的自动先停 |
| 停止 | `POST /timer/stop` | 一条 `session.completed`，清活状态 |
| 取消不记录 | `POST /timer/cancel` | **什么都不写**，只清活状态 |
| 补登 | `POST /timer/backfill` | 一条 `session.completed`，带 `source=manual-backfill` |

「暂停」不在这张表里——它是纯前端的：停表入账 + 本机记住停的是谁，
点继续时重新 start 并把之前的累计加回显示。后端没有"暂停"这个概念，也不需要有。

## 前端

零构建。`web/` 下每个 `hex-*.js` 是一层，加载顺序在 `index.html` 里写死：

| 文件 | 职责 |
|---|---|
| `hex-data.js` | 纯逻辑：把 tree 变成蜂巢坐标（扇区 → 环 → 格位），算热度、深浅 |
| `hex-layout.js` | 只做几何：算每个元素该在哪、多大、相机缩多少，再落到 transform 上 |
| `hex-borders.js` | 分区界线：逐格逐边判，边界线是晶格邻接的推论，不是画多边形 |
| `hex-app.js` | 建 DOM、管状态、绑事件 |
| `hex-timer.js` | 长按 → 计时；`hex-genie.js` 神灯动画；`hex-spark.js` 粒子 |
| `hex-center-ctl.js` | 中心格的 完成 / 暂停 / 取消不记录 |
| `hex-zone-edit.js` | 分区名：短按开规划面板，长按进编辑模式拖方位 |

几何常量只有一份（`hex-layout.js` 顶部），别的文件从它取。
颜色一律走 CSS 变量（`tokens.css`），JS 不产出色值。
